## 已确认的结论与证据边界

已定位三个实现/验证缺口：相对几何条件被自动转换成绝对坐标硬约束；原版的逐步刚体
对齐在该分支被跳过；native replay 实际使用了硬约束修改过的噪声输入。
已有输出直接证实严重断链发生在生成阶段。上述缺口构成具体、可追踪的失败机制候选，
不是“数据少”或“loss 与指标不同”这样的泛泛解释。

但现有文件没有保存当前模型在同一初始噪声下、逐项修复这些缺口的反事实轨迹。
因此不能诚实地把某一行宣称为全部 24 个失败的唯一原因，也不能保证修改后成功率恢复。
初始化与最终权重的四链比较，以及外部原版/最终 Omni 比较，仍是不同的对照。

以下数值直接摘自保存的 PDB，没有重新运行模型或评分。

| 同一候选 | Cα 24 的坐标 (Å) | Cα 25 的坐标 (Å) |
|---|---|---|
| 原版 | (-10.062, -1.948, -4.691) | (-10.609, -4.270, -7.637) |
| Omni 400 步 | (-3.932, 6.723, -16.484) | (-136.375, 203.375, -102.312) |

Omni 两个相邻 Cα 仅 y 分量就相差 196.652 Å，已远离正常连接的尺度。一次整体刚体
对齐不能消除这类内部断裂。该候选原有评分 best-of-8 scRMSD 为 106.596 Å。
MPNN/ESMFold 收到的骨架已经不连续；这不是只改 pLDDT 阈值就能解决的问题。

证据：

## 2. 原版条件被转换了语义，零反馈不再意味着原版完整采样

`generate.py:102–106` 从 `token_distance_mask` 推出 `hard`，将结构组的可见骨架直接
作为 `Observations.coordinate_mask`。YAML 本来表达的是结构组/相对几何条件，没有
独立的“用户要求绝对坐标硬固定”字段参与此决定。

随后 `../omni_joint/model.py:218,244,247,252,261` 对初始噪声、网络输入、网络输出、
更新后的坐标以及最终输出硬覆盖 motif 坐标；第 248 行以 `and not anchored` 排除了
有 motif 时的 reverse alignment。代码中没有先将整个预测结构按已知 motif 对齐到
锚点坐标系的步骤。

实际原版 `upstream/src/boltzgen/resources/config/design.yaml:90–92` 开启了
`mse_rotational_alignment` 和 `alignment_reverse_diff`。原版采样器
`upstream/src/boltzgen/model/modules/diffusion.py:588–615` 对全部坐标加噪，并在每步
更新前进行刚体对齐，不执行上述局部硬覆盖。

这不是仅增加了一个零初始化反馈层：推理所求的条件和数值更新流程一起改变了。
原文第 4.6 节也明确区分软模板/相对姿态约束与绝对坐标硬观察。
硬约束本身可以是合法任务，但不能通过一个 distance-mask 自动混同这两种任务语义。

可能的破坏机制很具体：如果网络给出的全链预测相对锚点发生刚体偏移，只替换 motif
而不转换整条链，会改变 motif 与生成部分之间的距离，造成断链。第 1 节是这种机制
需要解释的实际失效输出。缺少逐步的 clamp 前坐标，尚不能判定该跳跃首次产生在哪一步，
或排除网络本身已经预测出断裂的情形。

不应直接删掉 `and not anchored` 就宣称修好：硬锚点任务的对齐必须同步处理完整状态、
观察坐标与返回坐标系；盲目恢复全原子对齐也可能移动合法硬观察。

## 3. native replay 的输入不是原版噪声输入

`corrected_model.py:63–64` 先构造 `target + sigma * noise`，随后把 motif 的噪声
清除；第 78 行把这个已经 clamp 的 `noisy` 直接传给原版教师，第 80 行同样传给学生。
两边确实使用相同输入，且没有给教师偷看隐藏序列；但输入分布不等于原版 design 的
原生扩散过程。原版训练见 diffusion.py:674，原版采样见 :588，均给全部坐标加噪。

因此当前项可称“新硬条件输入上的教师 MSE”，不能视为已经实现了覆盖原生 design
噪声分布的能力保持。它也没有约束整个采样轨迹。该项并非遗漏或恒为零：本次最终
design 验证记录的 replay 约为 0.10，不能把旧 LoRA 实验的 replay=0 问题套到本次。

这个缺口能解释为什么现有保持项不足以保证原版能力仍在；它不能单独证明全部退化均由
replay 导致。回放也是经验正则，本来就没有“绝不遗忘”的数学保证。

## 4. loss 下降实际学到了什么、没证明什么

固定验证输入为 sigma=8、chemical_t=0.5；目标来自真实结构，加噪后做单次去噪。
训练中未屏蔽的化学身份来自真值。生成时从高噪声开始，身份来自模型先前的采样结果。
这种真值腐化训练本身符合草稿，不应误报为标签泄漏或单独的实现 bug。

同一个当前模型、同一验证链的历史记录已经揭示 loss 与结构质量的分离：

| design 验证样本 / 指标 | 0 步 | 400 步 |
|---|---:|---:|
| 1k40：加权坐标 MSE | 0.578041 | 0.205679 |
| 1k40：smooth-lDDT loss，低为好 | 0.385365 | 0.382580 |
| 1k40：完整生成异常相邻 Cα 间距数 | 4 | 22 |
| 4gcn：加权坐标 MSE | 0.621464 | 0.234488 |
| 4gcn：smooth-lDDT loss，低为好 | 0.368910 | 0.371025 |
| 4gcn：完整生成异常相邻 Cα 间距数 | 8 | 2 |

来源：`runs/corrected-1729/validation-0.json` 与 `validation-400.json`；
`train.py:123–127` 固定了 probe 与 rollout 的种子和设置。两条链的完整生成变化不同，
不能说每条都因训练恶化；也不能把坐标 MSE 大幅下降说成局部几何已大幅改善。

新增四训练链完整生成比较中，scRMSD 30.76→21.93 Å，四链均改善，仍 0/8 成功。
这支持局部拟合收益，但不支持“已经学会设计，只是外部泛化差”。

MSE 的平均误差和局部几何损失不同；总 loss 还包含乘以 3.3371 的序列 CE 与 replay。
一个分量下降不保证另一分量或整条生成轨迹改善。不能仅根据 loss 的数值占比断言
梯度被某一项支配；梯度贡献要另看记录，不能靠 loss scale 猜测。

## 5. 为什么之前的检查没拦住

`train.py:69–91` 的 preflight 比较了同一个输入上的单次 denoiser 输出，结果 0.0。
它没有比较完整 native sampler 与零更新 Omni sampler。两边网络一致并不覆盖前述
硬投影、刚体对齐、返回帧和整个采样循环的差异。

既有独立评分核验重算了所有 384 条重折叠 RMSD；修正上游 mean-distance/RMSD 名称
问题没有改变任何成功标记。已有原始骨架的严重断链进一步说明不能把主要失败归咎于
那个评分修正。该结论不等于所有可能的评测问题都已排除。

## 修复范围与不能作出的保证

1. 将结构组相对几何条件和显式绝对坐标硬观察分开。原生 motif benchmark 的能力保持
   比较应走原版支持的条件语义；不能隐式加上新的硬坐标条件。
2. 原生条件下保留原采样器的整套坐标处理。真正的硬观察分支需要单独正确处理全链/锚点
   坐标系，不能简单局部覆盖来替代全链一致性。
3. 原生 replay 独立构造全坐标加噪的原版输入，师生都使用同一原版条件；completion 的
   硬观察腐化仍应按其自身定义处理。不要共用已 clamp 的噪声张量冒充原生分布。
4. 修复后的完整采样一致性和连接几何需要实际验证，才有资格评价修复效果；当前禁止
   compute，因此本次没有执行这些验证，也没有修改既有权重或宣布修复成功。

修改代码可以消除上述明确不一致，但既有 400 步权重是在旧目标/条件下优化的，不能从
源码审查推出它在新推理下必定恢复 18/24，更不能保证超过原版。这一保证目前不存在。
